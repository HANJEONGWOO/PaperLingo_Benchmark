# Internal API contract

Self-hosted FastAPI + SQLite + vanilla JS. Korean UI. All metrics are percentages (0..100), quality q is 0..1. No fabricated LLM scores. Original data immutable.

## Default code-only review (code-basic-v1)

`Settings.review_mode` / `PAPERLINGO_REVIEW_MODE` defaults to `code`; only `code` and `llm` are valid. In code mode, new HTTP submissions apply `code_quality(item, abstract)` to every item and return complete results immediately. No LLM health request, inference, or restart-resumption of old LLM work runs. `evaluate()` alone retains the legacy pending representation; the HTTP layer sets the report policy and calls `recompute()`. When policy is `code-basic-v1`, recompute always regenerates code results from source data, never from user judgments.

Four checks: `option_format` (four nonempty strings, each <=1000 chars; normalized internal IDs A-D), `no_duplicates` (NFKC/casefold/whitespace normalization), `designated_answer` (valid key and exact source blank restoration), `unique_source_answer` (exactly one normalized source-string match). Compact blank inference depends on the submitted key: this is source consistency, not independent semantic answer adjudication. Context sufficiency and semantic answer uniqueness are NOT checked. Existing source/span/duplicate-expression integrity failures remain prerequisites and force failure with issue reasons.

New report fields: `quality_policy_version='code-basic-v1'`, `review_mode='code'`, `score_mode='code'`; counts add `code_passed` and `code_failed`. Each quality has `status='complete'`, `source='code'`, `q=1|0`, `result='pass'|'fail'`, `checks:[{key,label,passed:bool,message}]`, `source_match_option_ids:[str]`, `semantic_reviewed=false`, `scoring_policy='code-basic-v1'`, `rationale`. `accepted_option_ids` and `option_assessments` are empty; gates/rubric are null. Never fabricate semantic judgments. Report `unique_answer_rate_pct=null`; `source_unique_answer_rate_pct` is the fraction of all items passing the source-uniqueness check.

The current formula remains exact-rq-v3: `100 * Recall * Qmatched`, but Qmatched is now the binary pass rate among matched items. G=0 remains null. Zero submissions with G>0 give final0. UI calls Q “일치 문항 통과율”, shows each check and pass/fail reasons, and clearly distinguishes source-string uniqueness from semantic uniqueness. JSON and CSV expose check results; CSV appends check_result, option_format, no_duplicates, designated_answer, unique_source_answer, source_match_options. Empty-paper rows have the same column count.

GET config adds review_mode and quality_policy_version; judge.automatic=false in code mode even when legacy judge credentials exist. GET judge/status returns mode=code, ready=true, configured=false without contacting any LLM. Code reports reject judge/skip-judge/reviews mutations with409; the UI hides those controls. Code mode rejects all manual LLM starts, including on old records. Legacy completed report scores are not migrated. Re-submit the input to create a code score. Comparison requires the same quality policy. The historical LLM/human contract below remains available with explicit `review_mode='llm'`; tests for that behavior must select it explicitly.

## Engine interface (core owner)

`Dataset(data_dir: Path)` exposes `.papers`, `.labels`, `.splits` (demo/evaluation -> list[str]), `.summary()`, `.version` (immutable source hash), `.demo_predictions(compact=True)` (public compact examples), `.demo_predictions()` (legacy internal fixtures). SPLIT_VERSION is evaluation-min5sentences-v3. The fixed public examples are 0911.3369, 1109.3182 and 1709.01217 (4+5+0 reference expressions); the previous evaluation pool contained all other 1,487 papers. Keep every paper whose abstract has at least five sentences: 1,044 evaluation papers with 4,832 references; 443 papers are excluded. No sampling, domain quotas, size cap or submission-file restriction applies. Example and evaluation sets remain disjoint but no longer exhaust the dataset. Evaluation IDs are sorted; no random split or seed is used. Tiny custom datasets use deterministic fallback examples, at most three. Split changes do not alter the source hash. The authored sample covers every example reference with structurally valid questions and four passing code checks: Recall, matched-question pass rate and final score are 100 in code mode. Semantic quality is not assessed. The bundled examples/predictions.jsonl, public sample and example-answer download contain identical compact records. `.search(query='', domain='', offset=0, limit=20)` returns paginated summaries.

`sentences.sentence_count()` uses versioned conservative rules (abstract-sentences-v1): punctuation boundaries, abbreviation/initial/decimal protection, TeX math masking, no line-wrap boundaries and no internal cuts inside balanced citation groups. Lowercase continuation after a period is not a cut. Count the final unpunctuated fragment, excluding isolated headings/numbers/formulas with fewer than two prose words. Cache counts by exact source text. This filter does not change question-context inference or scoring rules. Dataset summary exposes evaluation_filter; the split download also exposes per-paper evaluation sentence counts. New submissions still require the fixed current scope and reject excluded IDs; saved runs retain their original paper lists and denominators.

Dataset summary retains top-level counts for the complete source and exposes `split_stats[scope]` with paper, expression and domain counts for each current split. The homepage explicitly displays `split_stats.evaluation` (1,044 papers, 4,832 expressions, 147 domains), matching the evaluation download rather than the unfiltered source.

`Dataset.example_answer_metadata()` describes the public authored-demo-v1 examples, with quality_status=code-checked, quality_policy_version=code-basic-v1 and semantic_reviewed=false. The former bulk training-answer generator and training endpoints are retired. Existing reports retain their original scope, split_version and scores; changing the partition never rewrites stored records.

`evaluate(dataset, predictions: list[dict], paper_ids: list[str], scope_name: str) -> dict` raises `SubmissionError` with `.errors: list[str]` for fatal schema/contract problems. Predictions IDs must be within fixed scope, max5, duplicate paper/question IDs and unknown paper IDs are fatal. Item semantic/structure errors retained as scoreable errors; duplicates expressions count FP. Missing papers retain gold denominator. Input exact text and question structure follows below.

`recompute(report: dict) -> dict` mutates/recomputes metrics after quality update; returns report. Deterministic paper/question matching, no dependency on quality. `validate_review(payload: dict) -> dict` may be implemented by root.

Public question input (`compact-v1`): **expression_text, options, answer_id only**. `options` is an array of exactly four distinct nonempty strings; `answer_id` is an integer 0..3 (not bool, float, numeric string or A/B/C/D). Paper fields remain `paper_id`, `questions`; questions contains 0..5 entries.

Normalization derives stable question IDs, A/B/C/D option IDs and source spans. Select the first exact whole-word occurrence of expression_text in `abstract`, then the first whole-word occurrence of the correct option text inside that expression. The correct text must be an exact substring of expression_text. Use the source sentence interval containing the entire expression; do not cut a spanning expression at a sentence boundary. Replace that answer substring with `[BLANK]` for judging. Repeated occurrences always use the first one; this rule is advertised in the UI and schema. No label information is used to infer spans or choices. Preserve normalization policy metadata with new reports.

Legacy input remains supported for existing clients: question_id, expression_text, expression_type(optional), expression_span/context_span/blank_span {start,end}, options [{id:'A',text},...B/C/D], answer_id(A/B/C/D), learning_point(optional). Internal report/review/judge fields retain that representation. Spans use absolute Python Unicode [start,end) into abstract. Compact choices/answer indices mixed with legacy metadata are explicitly rejected; clients should use one format for each question. Extra fields are rejected. Wrong index/options/source spans are structural failures q=0, retained in the denominator. Missing/non-string expression_text is a fatal submission error. Duplicated expressions get matched=false and q=0 with a duplicate issue.

Legacy LLM report: {metrics_version:'exact-rq-v3', quality_policy_version:'auto-conservative-v1', score_mode:'reviewed'|'temporary', dataset_version, scope:{name,paper_ids,paper_count}, counts:{gold,predicted,matched,submitted_papers,missing_papers,quality_complete,quality_pending,quality_error,needs_review,quality_temporary,review_recommended}, metrics:{precision_pct,recall_pct,f1_pct,quality_all_pct,quality_matched_pct,unique_answer_rate_pct,structural_validity_pct,coverage_pct,empty_gold_abstention_pct,final_score}, papers:[{paper_id,paper_name,domain: string,abstract,submitted,gold_expressions:[str],missing_expressions:[str],items:[item]}]}.

Each item uses the normalized internal fields and adds context, matched:bool, structure_valid:bool, issues:[{code,message}], quality:{status:'pending'|'complete'|'needs_review'|'error', source:'structural'|'llm'|'human'|'temporary'|null, q:number|null, accepted_option_ids:[str], rubric:{plausibility:0..2,learning_alignment:0..2,distinctness:0..2,no_cues:0..2}|null, gates:{context_sufficient:bool,no_specialist_knowledge:bool,no_answer_leak:bool}|null, option_assessments:[{id,verdict:'acceptable'|'incorrect'|'uncertain',reason}], rationale:str, reviewer:str|null}}. In the legacy engine/LLM representation, initial valid quality pending, invalid structural quality complete/q0. Human and judge must use same fields. Criterion integer scores, gates all true and sole accepted option equals key for nonzero q. Uncertain -> complete q0, review_recommended=true, scoring_policy=auto-conservative-v1; retain uncertain assessments and reasons. Optional human review can replace this conservative score. HTTP/parse error -> error qnull. No judge result auto-accepts model-issued q. Review/retry/skip operations preserve the original metrics_version and formula; only newly created runs use the current metric. Updating quality_policy_version must not switch formulas.

Aggregate: P=T/N (0 if no N); R=T/G (null if G0); F1=2T/(N+G) (null if both0). Quality all is null until all submitted items complete, matched is null until all matched complete. Final null until every submitted item's quality complete; otherwise 100*R*mean(q of matched) for exact-rq-v3; existing exact-prq-v1/v2 (or missing version) retain 100*P*R*mean(q of matched); T0/G>0 =>0 after all complete; G0 =>null. Zero-submission N0/G>0 final0, quality means null. unique_answer_rate: fraction of all submitted with structurally valid, non-temporary, no uncertain assessments, resolved accepted single key and gates passed; null pending. Structural failures count denominator. Empty-gold abstention requires explicit submitted empty, missing is not correct abstention. Precision/F1 remain diagnostics. False positives do not lower or increase the v3 final score; duplicate expressions never create additional matches. Keep the maximum of 5 questions per paper, actual reference-count denominator, and review every submitted item before finalization. Field names exact for UI.

## HTTP contract (root owner)

GET /api/session -> {authenticated,auth_required,can_manage,public_read,csrf_token?}; login POST /api/login {password}, logout POST /api/logout. Cookie session. Mutations require header X-Requested-With: PaperLingo (CSRF same-origin policy). Readonly public can GET, admin can POST. Local no-password session can_manage true. Frontend must not show admin controls unless can_manage.

GET /api/config -> {dataset: summary,judge:{configured,automatic,model,base_url,concurrency},auth_required,public_read,can_manage,limits:{max_upload_bytes,judge_batch_size},metrics_version,version}
GET /api/papers?scope=demo|evaluation&q=&offset=&limit= -> {items:[{paper_id,paper_name,domain,gold_count?}],total,scope}; default demo. gold_count is available only for example papers in this explorer endpoint
GET /api/papers/{paper_id} -> paper metadata + abstract; example papers additionally include expressions, all other papers (including excluded short abstracts) instead include reference_hidden=true. Access is determined by the server public-example allowlist, never a caller-supplied scope query
GET /api/splits?download=1 -> {dataset_version,split_version,splits:{demo,evaluation},example_answers:{version,quality_status,...},evaluation_filter:{minimum_sentences,sentence_policy_version,source_paper_count,eligible_paper_count,excluded_paper_count,sampling},evaluation_sentence_counts:{paper_id:count}}; JSON attachment when requested
GET /api/datasets/{demo|evaluation}/{papers|labels|answers} -> JSONL attachment. papers contains normalized abstract and metadata; labels contains exact original expression records. Evaluation exposes papers only; labels and answers return404 even for direct URLs. Both evaluation reference-download buttons remain visible but disabled (native button elements without href). Examples expose all three resources; answers is compact-v1, identical to /api/sample and scores 100 in code mode. Semantic quality remains unreviewed. Retired train download paths return422. Corresponding files share the split's exact ID order. Downloading never queues inference or creates runs.
GET /api/sample -> {scope:'demo',paper_ids:[...],predictions:[compact-v1 papers]}; downloadable fixture via query download=1 returning paperlingo-format-example.jsonl
GET /api/schema?lang=ko|en (default ko) -> friendly compact-v1 field contract, answer index bounds, automatic context policy, sample and legacy_supported flag. Only help strings depend on language; field names, types, limits and sample data are identical.
GET /api/runs -> {items:[run summary]}
POST /api/runs {name,scope?:'demo'|'evaluation'|null,paper_ids?:[...],predictions: string JSONL or array} -> full run. Omitted/null scope is inferred from submitted paper IDs: a nonempty submission containing only public example IDs uses the entire demo split; otherwise use the entire evaluation split. Empty arrays use evaluation. Mixed example/evaluation submissions are rejected with422, as are unknown, excluded or invalid IDs; no rows are silently dropped. Explicit scopes remain authoritative. Optional paper_ids must exactly match the full resolved scope without duplicates. Missing papers remain in the Recall denominator. Retired scopes return422 for new submissions; historical records retain their stored scope/IDs/metrics. New reports include split_version, while old reports are not migrated. GET /api/schema advertises scope_optional=true and scope_selection=automatic_when_omitted; scopes still lists the two actual datasets.
GET /api/runs/{id} -> full run
All full-run response boundaries (creation/detail/reviews/skip/JSON export) hide non-example paper gold_expressions and missing_expressions, replacing them with reference_hidden=true, gold_count and missing_count. Projection uses the public-example allowlist, including historical mixed scopes and papers removed from evaluation by the length filter. Stored reports retain full references for scoring/recomputing and are never modified by reads. Predictions, match feedback and metric values remain visible; CSV contains submitted items, never the withheld reference list. This prevents an empty evaluation submission from downloading the answer key. Only demo references remain visible, including when reading historical training reports. UI treats hidden references separately from an empty reference set and uses the supplied counts for summaries and missing-expression filters.
Full run: {id,name,created_at,updated_at,status:'awaiting_review'|'queued'|'judging'|'complete'|'needs_review'|'error',judge_meta?:{...},report:<above>,is_demo:boolean}. Summary includes {id,name,created_at,status,scope,metrics,counts,is_demo,score_mode,quality_policy_version,metrics_version}.
In llm mode, POST /api/runs automatically queues all valid pending items when judge is configured. Runs execute serially; judge_batch_size is an internal chunk size, not a per-run limit. Browser closure does not cancel work. Persist queued/interrupted work and resume at startup, preserving completed reviews.
POST /api/runs/{id}/judge -> {status:'queued'|'judging',count,remaining_after_batch:0} queues pending/error/legacy-needs_review/temporary items, excludes resolved human/llm. Requires judge config; duplicate start requests are idempotent while active. Errors are retried only on explicit request, with bounded adapter retries.
POST /api/runs/{id}/skip-judge -> updated full run. Invalidates the job token and atomically gives ALL structurally valid items temporary q1, including previous completed reviews. Preserve previous decisions in review history; structural failures stay q0. An in-flight inference drains while its late result is discarded; no further items start. source=temporary, rubric/gates=null, assessments/accepted=[]; do not invent evidence. UI/JSON/CSV/history identify temporary scores; exclude them from regular comparisons. Re-judge or optional human review replaces temporary credit.
POST /api/runs/{id}/reviews {paper_id,question_id,accepted_option_ids:[ids],rubric:{...},gates:{...},rationale,reviewer} -> updated full run; structural invalid cannot override, not allowed while queued/judging. After skip returns, optional human review is allowed even while an old inference drains.
GET /api/runs/{id}/export?format=json|csv -> download.
GET /api/health -> {status:'ok'}

## Judge module (judge owner)

`JudgeConfig(base_url:str,api_key:str,model:str,timeout:float=90,max_retries:int=2)`
`async judge_item(item:dict,config:JudgeConfig) -> dict` returns quality object above with status. Never throws credentials/raw provider text. Server-supplied endpoint only, no browser secrets. Use httpx async chat/completions OpenAI-compatible protocol, response_format JSON optional graceful compatibility. Model and endpoint explicitly set, no assumed model identifier. Prompt no answer key, source text, expression metadata/learning_point that can disclose key. Pass context+options and level only. Shuffle deterministically stable based question/context; preserve option IDs or remap correctly. Prompt treats candidate content as data. Strict validate fields, known option IDs exactly once, bool/int types and bounded values. Uncertain is complete/q0 with optional review recommended; preserve uncertainty evidence. Network/invalid responses error, no final score. Judge module owns prompts/judge_v1.txt and tests/test_judge.py and scripts/example_generator.py (optional generator CLI with no labels access). Human review validation can share `quality_from_review(item,payload,source='human')` in judge module returning normalized quality or raises ValueError. Need rationale/reviewer required for manual. Judge q is computed by code.

## UI (frontend owner)

The homepage attaches content hashes to the four JS/CSS asset URLs at server startup. HTML and scripts/styles require cache revalidation (`Cache-Control: no-cache`); API responses remain `no-store`. Restart the web service after deploying UI files. Versioned asset URLs bypass previously cached unversioned scripts without clearing the user's language preference.

Own paperlingo/static/index.html, app.js, styles.css, i18n.js and translations.js. No build tool or CDN dependencies. Korean/English research dashboard, sidebar, upload panel with drag-drop + paste, evaluation name and automatic server-selected scope (no scope selector), sample load/download. Reference-data navigation and its example/evaluation explorer selector remain available. Dataset stats, report cards P/R/F1/Q/final with pending never0, run history + select2 compare, paper/item filters and details, answer options, gold matches/misses, structural issues, human rubric review form, immediate four-check pass/fail details and export; historical LLM records retain review controls and progress displays. New code records hide review/skip controls. Responsive, keyboard labels/status, no innerHTML of user content. Show demo as manually authored format sample not a real model benchmark. Dataset explorer and methodology guide tabs recommended. Frontend reads above API contract.

Language selection uses localStorage key paperlingo_language (ko/en), falling back to browser language (ko-* -> ko, otherwise en). Switching updates bound text/attributes and document.lang without navigation, network requests or rebuilding forms/reports; inputs, filters and open details stay intact. Storage failures leave switching functional in the current tab; storage events synchronize same-origin tabs. Translate UI and known system messages, preserving raw research/submitted text, human/LLM comments, API records and exports. Translation templates preserve numbered placeholders; optional browser regressions use requirements-ui.txt and an isolated code-mode server.
