01 / EXPRESSION MATCH

좋은 표현을 찾았나요?

같은 논문 안에서 선정한 전체 표현과 참조 라벨의 문자열을 정확히 비교합니다. 빈칸으로 만든 일부만 비교하지 않습니다.

Precision = 일치 표현 / 생성 표현
Recall = 일치 표현 / 참조 표현
F1 = 2 × 일치 표현 / (생성 표현 + 참조 표현)

전체 개수를 합산하는 micro 지표입니다. 중복 표현은 한 번만 일치로 인정하며, 평가 대상에 속한 미제출 논문의 참조 표현도 분모에 포함합니다.

02 / QUESTION QUALITY

좋은 보기를 만들었나요?

LLM은 정답 키를 보지 않고 각 보기의 허용 가능성을 판단합니다. 사람도 동일한 기준으로 검수할 수 있습니다.

  • 문맥상 정답이 유일하고 지정된 정답과 일치
  • 충분한 문맥, 전문 지식 불필요, 정답 노출 없음
  • 오답의 그럴듯함 · 학습 목표 관련성
  • 오답 간 구별성 · 불필요한 정답 단서 없음

품질 4개 항목을 각 0–2점으로 평가해 합계를 8로 나눕니다. 단일 정답 등 필수 조건을 충족하지 못하면 0점입니다.

03 / COMPOSITE SCORE

최종 점수

100 × P × R × Qmatched

P와 R은 0–1의 비율, Q는 참조 라벨과 일치한 문항의 평균 품질입니다. 모든 제출 문항의 검수가 끝나야 최종 점수를 확정합니다.

이 식은 프로젝트의 초기 복합 평가 기준입니다. 실제 학습 효과를 직접 측정한 점수는 아닙니다.

DATA & VALIDATION

비교가 공정하려면

  • 개발·검증·최종 평가 분할은 분야별 7 / 1 / 2
  • 최종 평가 전에 프롬프트와 기준 고정
  • 생성 모델에는 참조 정답을 제공하지 않음
  • 라벨과 기준 수정 시 버전을 남기고 재평가
  • LLM 검수는 사람의 표본 검수로 확인

검수 대기, 불확실한 판단, API 오류는 0점으로 바꾸지 않습니다. 구조 오류는 문항 품질 0점으로 처리합니다.

SUBMISSION FORMAT

생성 모델 연결하기

전체 스키마 보기 ↗

JSON 배열 또는 논문당 한 줄인 JSONL을 제출합니다. paper_id와 questions를 포함하며, 논문당 문항은 0–5개입니다. 각 문항에는 expression_text, 문자열 4개인 options, 0–3의 정수인 answer_id만 입력합니다.

{
  "paper_id": "0911.3369",
  "questions": [{
    "expression_text": "a function of",
    "options": ["of", "to", "at", "by"],
    "answer_id": 0
  }]
}

answer_id는 보기 배열의 순서이며, 첫 번째 보기는 0, 마지막 보기는 3입니다. 위 예제에서는 of가 정답이고 a function [BLANK]로 구성됩니다.

표현과 정답 보기는 단어 경계가 맞는 첫 출현을 사용합니다. 원문에서 표현을 찾은 뒤, 표현 안의 정답 부분을 빈칸으로 만들고 표현이 포함된 원문 문장을 문맥으로 사용합니다. 평가 결과에서 의도한 문맥과 빈칸인지 확인하세요.

위 코드는 직접 작성한 입력 형식 예제입니다. 여러 논문이 포함된 예제 파일도 내려받을 수 있습니다.
