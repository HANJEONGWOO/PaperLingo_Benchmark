01 / EXPRESSION MATCH

좋은 표현을 찾았나요?

같은 논문 안에서 선정한 전체 표현과 참조 라벨의 문자열을 정확히 비교합니다. 빈칸으로 만든 일부만 비교하지 않습니다.

Recall = 일치 표현 / 실제 참조 표현
Precision = 일치 표현 / 생성 표현 (보조)
F1 = 2 × 일치 표현 / (생성 표현 + 참조 표현) (보조)

전체 개수를 합산하는 micro 지표입니다. Recall의 분모는 평가 대상의 실제 참조 표현 수이며, 미제출 논문의 참조 표현도 포함합니다.

논문당 5개는 최대 개수이며 반드시 5개를 채울 필요는 없습니다. 정답과 일치하지 않는 표현이나 중복 표현을 추가해도 일치 수는 늘지 않습니다.

02 / CODE CHECKS

보기의 기본 조건을 충족하나요?

LLM 호출 없이 각 항목을 통과 또는 실패로 판정합니다.

  • 보기 형식: 비어 있지 않은 문자열 4개
  • 중복 여부: 대소문자·공백·유니코드 표기를 정규화한 뒤 서로 다른 보기
  • 지정 정답: 유효한 정수 인덱스 0–3, 해당 보기가 원문 빈칸과 정확히 일치
  • 유일한 정답: 원문 빈칸과 일치하는 보기가 정확히 1개

유일성은 문자열 비교 기준입니다. 간단 입력 형식에서는 지정 정답으로 빈칸을 구성하므로, 이는 원문과의 일관성 확인입니다. 의미상 다른 보기도 정답이 되는지는 확인하지 않습니다. 문맥 충분성과 오답의 교육적 품질도 추후 검사합니다.

03 / COMPOSITE SCORE

최종 점수

100 × R × Qmatched

R은 Recall을 0–1로 나타낸 비율이고, Qmatched는 참조 라벨과 일치한 문항중 코드 검사를 통과한 비율(0–1)입니다. Precision과 F1은 보조 지표이며 v3 최종 점수에 곱하지 않습니다. 입력 구조가 유효하고 네 항목을 모두 통과한 문항은 1, 실패한 문항은 0으로 집계하며 제출 즉시 점수를 표시합니다.

Recall 60% · 일치 문항 통과율 80%
100 × 0.6 × 0.8 = 48점

예: 참조 표현 10개 중 6개를 찾고, 그중 5개 문항이 검사를 통과했다면 100 × (6/10) × (5/6) = 50점입니다. 원문에 없는 표현이나 잘못된 위치 등 입력 구조 오류는 실패로 남깁니다.

현재 지표는 exact-rq-v3, 검사 기준은 code-basic-v1입니다. 기존 LLM·사람 검수 기록은 당시 기준을 유지합니다. 이전 v1·v2 기록은 당시의 100 × P × R × Qmatched 산식과 점수를 유지하며, 서로 다른 기준의 점수는 직접 비교할 수 없습니다. 이 점수는 실제 학습 효과를 직접 측정한 값이 아닙니다.

SUBMISSION FORMAT

생성 모델 연결하기

전체 스키마 보기 ↗

JSON 배열 또는 논문당 한 줄인 JSONL을 제출합니다. paper_id와 questions를 포함하며, 논문당 문항은 최대 5개이며 0–5개를 제출할 수 있습니다. 각 문항에는 expression_text, 문자열 4개인 options, 0–3의 정수인 answer_id만 입력합니다.

{
  "paper_id": "0911.3369",
  "questions": [{
    "expression_text": "a function of",
    "options": ["of", "to", "at", "by"],
    "answer_id": 0
  }]
}

answer_id는 보기 배열의 순서이며, 첫 번째 보기는 0, 마지막 보기는 3입니다. 위 예제에서는 of가 정답이고 a function [BLANK]로 구성됩니다.

표현과 정답 보기는 단어 경계가 맞는 첫 출현을 사용합니다. 원문에서 표현을 찾은 뒤, 표현 안의 정답 부분을 빈칸으로 만들고 표현이 포함된 원문 문장을 문맥으로 사용합니다. 평가 결과에서 의도한 문맥과 빈칸인지 확인하세요.

위 코드는 직접 작성한 입력 형식 예제입니다. 여러 논문이 포함된 예제 파일도 내려받을 수 있습니다.
